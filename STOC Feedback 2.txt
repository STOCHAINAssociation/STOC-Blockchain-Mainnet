STOC-1 Issues with Inconsistent Token ID Handling
Lines：x\stoc\keeper\token.go
●Issue Description: When calling the CreateToken function to create a token, this function invokes the SetToken function to store the new token information in mainStore and indexKey, using token.Id as the key. Normally, token.Id is the token's minimalDenom. However, if an exception occurs and token.Id is null, the function generates a new random number using uuid as the token.Id. It is important to note that at this point, the token.Id stored does not match the minimalDenom.If the inconsistency mentioned above is not considered during operations that involve calling the GetToken function to query token information, issues may arise.
For example, when the Creator calls the MintToken function to mint coins for the owner, it uses the symbol, which is the minimalDenom, to check if the token exists. If it exists, it calls sdk.NewCoin(symbol, amount) to create the token instance. However, when token.Id and minimalDenom are inconsistent, if MintToken passes in the symbol as minimalDenom, the function will fail when calling GetToken because it cannot find the token. Conversely, if MintToken passes in the symbol as token.Id, the token can be found, but it will fail due to using token.Id instead of the token's minimalDenom when creating the coin with NewCoin.
  

* Recommendations: It is recommended that the MintToken function use token.Id as a parameter during the call, and when calling sdk.NewCoin, it should use the retrieved token.MinimalDenom for minting the coins.Additionally, if there are future updates to the interface, it is important to consider this discrepancy.

STOC-4 No Limit on Number of query pages
Lines：x\stoc\keeper\query_token.go
●Issue Description: Users can query the registered token information through the Query's RPC Tokens method. When querying, a limit parameter can be passed in, which determines the number of pages displayed in the result. However, the code does not restrict the size of this value, allowing a maximum input of 18,446,744,073,709,551,615 pages, which is the maximum value representable by uint64. Additionally, since this interface can be called by anyone, it may lead to a Denial of Service (DoS) attack.
  

  

* Recommendations: It is recommended to restrict the pagination limit for the limit parameter.
